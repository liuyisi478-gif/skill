# 数形结合与解答配图

## 何时必须画

先判断图能否让学生更容易看懂关系或完成题目要求，不用等用户另说“请配图”。以下情形须实际绘制并放入交付Word：

| 情形 | 应交付的图 |
|---|---|
| 数形结合更直观 | 线段图、份数图、数轴、相遇/追及示意、面积切分图等，选择能直接承接列式的一种 |
| 原题要求作图、操作 | 完整成图，保留必要原始元素和新增内容；可按需给关键中间图 |
| 解法增加辅助线/补形/平移旋转 | 带新增构造的解答图，端点、交点、阴影与正文一致 |
| 几何体需截面/展开/切割/组合 | 立体示意图及必要截面或展开图，清楚表达空间关系和新生成的面 |

普通一步算术、图对理解没有帮助时不强加装饰。原图已有且无新增构造时，可复用清晰且正确的原题局部图；裁剪不会增加辅助线，需要新增内容就准确重绘或标注。无法确认点位/尺寸时先标存疑，不能凭空补图掩盖源材料缺失。

## 绘制前的图形清单

质检记录每题是否需图、图型、依据、标签、对应段落和验证结果。区分：原题已知、由条件推得、新增辅助构造。不能把尚未证明的长度/角度或结论画成额外已知；用未知长度画示意图时写明不按比例，不能让学生通过量图猜答案。

平面几何核点在线段/延长线上、交点、平行/垂直、等长、阴影区域和连接顺序。几何体先按三维坐标或明确拓扑关系建模，再选择投影；核对顶点/棱/面数和遮挡，投影图上的角与边长不等于实际角与长度。截面和展开图还需核对哪些面相邻、切割增加几个面。

## 绘图方法与风格

数学图优先使用程序或矢量绘图准确构建，不用艺术生成图代替精确的连线、标签和几何关系。不限于固定模板：复杂图可写专用代码或用其他准确绘图工具，不能因为工具不支持某形状就只交文字。

- 原有可见边用实线，隐藏边用虚线，辅助线用细虚线/点划线并在图注说明；若隐藏边和辅助线同为虚线，用线宽、节奏和图注明确区分。灰度打印仍可辨，不只靠颜色。
- 点名、已知量、单位、方向、刻度完整；新增点在文字中定义。标签不压线、不重叠、不裁切，切面/阴影不挡关键结构。
- 在Word实际尺寸看仍清楚，文字一般不小于约9磅；可加宽图或把复杂图拆为多图，不硬缩小。
- 保留能复绘的SVG/场景源稿在工作目录。正文公式使用OMML；图里只放点名、简单已知值/单位等标签，复杂算式和推导放图旁，不能整段公式截图化。
- 图片嵌入Word，不要求读者另开链接。图像本身不等于可逐线编辑；如用户进一步要求编辑线条/图形，应改用可编辑形状/矢量对象并单独验证，不虚称PNG可编辑。

## 内置通用绘图工具

`python scripts/draw_math_diagram.py SCENE.json OUT.png --font <可用中文字体>`，依赖Pillow。生成高分辨率PNG及同名SVG源稿；不是自动识图工具，须先核定数学关系。默认3倍像素，1000单位宽的图生成3000像素，嵌入约10–12厘米时足够清晰。

场景结构（坐标原点在左上，y向下）：

```json
{
  "size": [1000, 600],
  "points": {"A": [150, 400], "B": [750, 400], "C": [450, 100]},
  "items": [
    {"type": "polygon", "points": ["A", "B", "C"], "width": 2},
    {"type": "line", "from": "C", "to": [450, 400], "dash": [8, 5], "width": 1.5},
    {"type": "label", "at": [450, 70], "text": "C", "anchor": "center", "size": 36}
  ],
  "constraints": [{"type": "perpendicular", "points": ["A", "B", "C", [450, 400]]}]
}
```

支持line、arrow、polygon、polyline、ellipse、label；线可配置width/color/dash，面可fill灰色。圆是横纵半径相等的ellipse。圆弧、复杂曲线、展开图等可用专用代码绘制，不能用错误图形凑支持。复杂表达式不放label，避免把应可编辑的公式栅格化。

可选constraints支持on_segment（点、端点、端点）、parallel、perpendicular、equal_length（两线段的4端点）；只检验给定二维坐标，不证明建模和题意正确，也不能用于立体投影图上的实际长角关系。无效约束、缺点、零长度线、标签出界或未知图元报错，须修复，不能忽略后交图。

## 插入Word

题目源记录示例：

```json
{
  "diagram_required": true,
  "diagrams": [
    {"path": "figures/q16.png", "caption": "第16题解答图（细虚线DF为辅助线）", "after_paragraph": 0, "width_cm": 10}
  ]
}
```

after_paragraph是正文段落列表从0开始的索引，-1表示首段前。图紧邻首次实质引用它的步骤；同题多图按步骤插入，不统一堆在题末或卷末。宽度按标签清晰度与版心选择，禁止变形拉伸。图注和图片尽量同页，题号/答句/归类不孤立。

导出器会拒绝“必配但无图”和无效位置/宽度/路径，保存后检查嵌入图数及图片关系。但“漏标diagram_required”的语义错误仍靠逐题自检，不能宣称脚本自动判断所有题是否需图。绘图/嵌入失败时明确列缺项，不把纯文字稿称为完整交付。最终必须渲染Word逐页核图文、线条、字号、标签与分页。

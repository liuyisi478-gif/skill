# 小学奥数教辅解析

目标：答案可靠、关键推导完整、文字精练、可直接编辑排版。用户本次指定的格式和风格优先于默认规则。

## 资源入口

- 写解析前读 [editorial_style.md](references/editorial_style.md)：篇幅控制、关键步骤及用户认可的几何样例。
- 排版前读 [format_spec.md](references/format_spec.md)：卷头一框答案表、编号和分题型格式。
- 生成 Word 前读 [word_delivery.md](references/word_delivery.md)：原生公式、导出工具与验收。
- 遇数形结合、作图、几何辅助线或几何体，读 [diagram_spec.md](references/diagram_spec.md)：配图判定、绘制、插入与图形核验。
- 逐题自检用 [selfcheck.md](references/selfcheck.md)；工具范围查 [tool_tiers.md](references/tool_tiers.md)；具体标签查 [model_taxonomy.md](references/model_taxonomy.md)。

## 核心要求

1. **先确认题意。** 数字、单位、选项及图形关系逐项核对，不根据图形外观补条件。关键条件读不清、缺失或矛盾时保留存疑。题干复原放质检文件，学生稿不抄完整题干。
2. **独立求解与验算。** 先求答案，再核对参考答案。程序重复同一错误公式不算独立验证，须另查原始条件、守恒量、量级或另一模型。可穷举、模拟、递推的题执行题目专用代码，可复用 `scripts/verify.py`；只运行工具箱自检不等于验过本卷。
3. **保留关键数学链。** 数量关系、单位“1”、重要中间量、局部比转整体份额、底高/等积关系、分类边界、最优性依据必须显式出现。不能用长段文字代替关键算式，模型名不能代替本题中的对应关系。
4. **用必要解释控制篇幅，不压成算式串。** 选择、填空也要讲清主要算式求什么、为什么这样算，重要中间量有名称和依据。不能因答案已填出就省略解释；只有口算题默认只给答案。一题默认一个适龄主解法，先补文字与算式组成的推导，再删重复题意、重复结论和无必要栏目，不设强制字数。内部双通道和验算通常不进学生稿。
5. **正式交付 `.docx`，公式可编辑。** 使用 Word 原生 OMML 公式，不用公式截图、图片或未转换的 LaTeX 冒充。Markdown、JSON、渲染图和日志只作工作文件，用户明确要求时才另交。
6. **卷头照样图。** “快速对答案”标题下为同一个外框表格：上格内同时有原卷大题序号、题型名、小题号/范围和答案，只列实际存在的选择题、填空题；下格为详解提示，不新增计算/解答题答案行。两类都没有时整块省略。
7. **具体知识点照实标。** 每题末【题型归类】，主模型在前，用全角「＋」连接，通常1–3个、最多4个。不标“应用题”等大类；词表无对应项时在项前加 `〔新拟〕`，文末登记新增清单，不硬套旧名。
8. **需要图帮助解题，就在 Word 中交付画好的图。** 数形结合能显著帮助理解时主动画线段图、示意图、数轴或面积图；作图题交实际成图；几何/几何体需要辅助线、截面、展开或分割时交对应解答图，不能只写绘图指令。图不能凭空添加已知条件，也不能代替必要的文字和算式。

## 工作流程

### 1 接收、复原与定位

确认输入、年级及明确的篇幅/版式要求。有用户认可的原题和解析时提取可复用规则；只有样例时不假称读过其 GPT 项目指令或历史聊天。

一题一单元，记录“大题序号＋题型＋小题号”，保留重新从1编号、跨页续题和多小题。PDF 使用当前可用的 `pdf` 技能或渲染工具，不依赖未安装技能；自动识别须与原图对照。

### 2 逐题求解并记录证据

- 复核全部条件，独立求解，再用不同途径核验：另一解法、从原条件模拟/枚举、代回全部条件等。
- 枚举说明搜索范围及完备依据；达到上限不声称穷尽。样本重复只提供候选周期，还要查完整递推状态或证明。最值同时有界限论证与达到界限的构造。
- 参考答案只用于对账；分歧复查读题、选项映射、条件和单位，记录双方答案与证据，不为迎合参考而改答案。
- 真有问题时该题最前写【题目核查】：问题→影响→待补资料或修正建议；未经确认不修改题意，只输出已确认部分。

### 3 改写为教辅稿

按 editorial_style 的“关系—列式—结果”组织。先列关键步骤骨架，再用短句连接；重要中间量求出后接着用于下式。几何写明共用/等高/等底对象及比的对应顺序；辅助线说明端点并画出对应解答图。计算题完整逐行脱式。

逐题判定配图需求：数形结合有助理解、题目本身要求作图、解法引入辅助线/补形/切分/截面/展开时，须执行 diagram_spec，实际制图并嵌入 Word。普通一步计算不强加装饰图；不清楚的原图关系须先核实，不能用画得漂亮掩盖识图存疑。需要图的题在源记录标 `diagram_required: true`，并列明类型、点位和新增构造；绘制失败须列为交付缺项，不能用纯文字冒充完整成稿。

【思路分析】【题图分析】【易错警示】【一题多解】按需添加，不重复正文。学生稿不用丙档，乙档按 tool_tiers 标明；内部复核可用更广工具，不能直接复制给学生。

两遍编辑：先查文字和算式能否共同讲清每个关键步骤，再删冗词。选填题不能只做到“式子连续”，还须让学生理解式子的对象、依据和结果用途。必要的解释不当作冗词删除，不通过缩小字号、压行距补救篇幅，不自设强制字数。

### 4 同源排版和 Word 验收

答案台账同时生成卷头与正文，避免分别手填。详解标题默认“详解详析”，正式 Word 不重复输出独立“第X题”标题，保留原卷大题名和正文小题号。

可用 `scripts/export_docx.py` 从结构化 JSON 导出；只支持明确列出的初等公式，未知命令会报错，须改用其他经过验证的原生 OMML 路径，不可丢符号或转图片。若使用 Markdown 草稿，运行 `scripts/lint_md.py`，ERROR 清零；仅代表草稿格式检查，不替代 Word 或数学验收。

配图可用 `scripts/draw_math_diagram.py` 从核定场景生成高清 PNG 与 SVG 绘图源；复杂图可用其他准确的程序/矢量绘图方法，不能因该工具没有专门模板就退回纯文字。导出器支持每题 `diagrams` 列表，在指定段落后插入多图；已标必配图但缺图时拒绝导出。导出后核对实际嵌入图数、图片关系、点位、尺寸及清晰度，不能用外部图片链接代替嵌入。

按 word_delivery 完成 ZIP/XML、Document 重开、源公式与 OMML 数量及内容检查，再渲染逐页检查。无渲染器时明确“结构检查通过，视觉检查未完成”，保留待验收状态，不宣称已全面验收。

### 5 交付和质检

默认交付两份：

- `<卷名>-解析.docx`：快速表、解析、必要的数形结合图/成图/辅助图、具体题型归类；有新拟则附登记清单。不含完整题干、内部验证或置信标签。
- `<卷名>-质检.docx`：逐题题干复原（含原页/题号）、读题疑点、独立验算方法和结果、参考答案分歧、置信档；末尾合并疑错清单、识别问题清单及置信分布。脚本记录路径、执行结果、枚举边界。

置信档：高置信＝题意明确且独立核验通过；建议复核＝仅一路有效、关键图形关系尚需确认、乙档方法或复杂分类仍需复核；存疑＝关键条件不清/矛盾、未穷尽、多解不明或参考答案冲突未解决。单通道可以输出已确认部分并降档，不强迫编造第二条路径。

## 批量策略

以整套卷为单位，逐题定稿再合并。可计算题按可复核工作量分批；图形、最值、歧义题每批不超过5道，标明需人工复核处。逐题基本核验不能被抽检取代；少量抽检不能估计“整批错误率”。

已授权整卷时持续完成整卷；局部疑问记录后继续其他题，不因达到某个题数无故停下要求“放量确认”。题库 ZIP 按可用的 `scan-pdf-to-question-package` 结构交付，本技能只负责解析质量。
